# 腕上节律圆屏赛博玻璃动态 UI 设计

## 目标

将现有 480×480 手表界面升级为“赛博玻璃 + 能量脉冲”视觉系统，并采用智能分级动效。界面只面向圆形表盘，所有重要信息和操作必须位于圆屏安全区内，不得被表盘边缘裁切。

改造只改变展示、动效和布局适配，不改变稳态训练、节奏拳评分、健康数据、传感器降级、会话时钟或前后台资源生命周期规则。

## 设计原则

1. 深色画布、分层半透明表面、低对比边缘和柔和内层光构成固定材质语言。
2. 青绿是稳态与健康数据的主色；橙色只用于活力模式、压力提醒、节拍目标和命中反馈。
3. 视觉面积以深色和中性玻璃为主，强调色不大面积铺满页面。
4. 动效用于表达状态变化，不作为持续播放的背景噪音，也不承载唯一信息。
5. 文本、数字和可点击区域始终优先于光效、装饰线和拖影。
6. 使用 openvela 支持的基础布局和动画能力，不依赖浏览器滤镜、复杂渐变或外部渲染库。

## 圆屏布局

设计基准为 480×480。页面仍以 480 设计宽度编译，但不再维护方屏专用结构、类名和测试契约。

- 主要信息与操作限制在中央约 340×400 的安全区域内。
- 顶部标题和剩余时间避开圆屏上缘；左右按钮、指标和说明避开最宽区域之外的裁切带；底部结束按钮与免责声明避开圆屏下缘。
- 常规圆屏使用完整尺寸；较小圆屏继续通过 `screenSize` 缩放尺寸和间距。
- 保留短视口保护规则，只用于确保圆屏模拟器或系统占用空间后主操作仍可达。
- `layout.js`、父页面和五个展示组件移除 `square` 分支。设备信息缺失或返回矩形形态时也使用安全的圆屏布局，不重新启用方屏版式。

## 视觉令牌

组件颜色按语义组织，避免每个组件各自散落不同的近似色：

- `canvas`：近黑青背景；
- `surface`：三档深青玻璃表面；
- `accent-calm`：健康、稳态、呼吸阶段的青绿；
- `accent-active`：节奏拳、压力提醒和命中的暖橙；
- `highlight`：主要文本、顶部高光和短促闪光；
- `text-primary`、`text-secondary`、`text-muted`：三级文字；
- `border-subtle`、`border-active`：静态边缘和状态边缘。

openvela 组件样式不能共享浏览器 CSS 变量时，各组件使用同名语义类和完全一致的令牌值。不得为了模拟玻璃而使用高亮白色粗边框或大面积高饱和色块。

## 首页

首页保留现有品牌、状态、心率、压力和两个训练入口，但将中央状态区升级为三层生命仪表：

1. 最外层是低对比玻璃边缘；
2. 中层是常驻的低频环境呼吸环；
3. 内层承载状态标题和两项健康数据。

健康数据更新时触发一次从核心向外扩散的脉冲。压力偏高或趋势上升时，边缘与状态点切换为暖橙，保持文字和结构不变。两个训练入口使用统一玻璃按钮，稳态按钮以青绿为强调，节奏拳按钮以暖橙为强调。

## 稳态训练

呼吸页的中央呼吸球是唯一强主视觉，并直接映射现有 `breathPhase`：

- `inhale`：核心和光环平滑扩大并增亮；
- `hold`：保持尺寸，光亮低幅悬浮；
- `exhale`：核心缓慢收缩，外层留下一次柔和尾晕。

剩余时间、阶段文案和呼吸节奏始终保持稳定位置，避免动画造成文字跳动。动画周期来自现有呼吸阶段，不另建独立业务时钟。

## 节奏拳小人

现有中心靶标替换为极简霓虹线框拳击手。人物由少量基础图形构成头、躯干、双臂和双腿，以保证 480×480 下的辨识度和运行性能。

人物动作与现有节拍状态绑定：

- 待机：低幅度上下弹跳，手臂保持防守姿态；
- 目标出现：身体轻微蓄力，目标侧手臂和暖橙节拍环进入准备状态；
- 命中：完成短促出拳，拳端触发双层冲击波；
- 漏拍：目标环快速衰减，不播放强烈失败闪烁；
- 连击：连击越高，出拳拖影和瞬时亮度越明显，但动作幅度不改变布局；
- 点击降级：传感器不可用时，点击人物区域继续调用现有模拟出拳事件。

得分、连击、剩余时间、节拍速度和降级文案仍由现有 props 提供。小人只负责展示，不拥有评分、传感器或计时状态。

## 结果页

稳态结果页和节奏拳结果页使用同一套完成语法：

- 页面出现时，主数字或完成标记分层进入；
- 完成标记只扩散一次光环；
- 指标卡保持低亮玻璃材质；
- 入场结束后回到低功耗静态状态；
- “完成”操作始终位于圆屏底部安全区内。

## 智能分级动效

动效分为四级：

1. **静息级**：首页和非交互状态只保留低频、低透明度呼吸光。
2. **数据级**：健康数据更新触发单次短脉冲，不循环叠加。
3. **训练级**：呼吸球和拳击小人跟随现有训练状态持续运动。
4. **反馈级**：命中、连击和完成触发 300–700 ms 的冲击波、拖影或光环。

应用隐藏时，现有生命周期会停止训练调度和资源；视觉动画也必须停止。返回前台后根据当前页面和训练状态恢复，不补播隐藏期间的脉冲、拳击或完成效果。

若平台不支持某个动画属性或设备性能不足，组件应退化到状态类切换。文字、颜色、数值和点击区域必须仍然完整可用。

## 组件边界与数据流

`index.ux` 继续是页面状态、健康订阅、动作传感器和训练时钟的唯一所有者。展示组件只通过现有 props 渲染，并通过现有事件报告用户意图。

允许新增纯展示字段，例如健康数据脉冲代际、拳击命中反馈类或结果页首次入场标记；这些字段只能由已有业务事件派生，不得创建第二套评分或训练状态。

`home.ux`、`breathing.ux`、`boxing.ux`、`steady-result.ux` 和 `boxing-result.ux` 各自维护模板与局部样式。共同色值和动效命名保持一致，便于后续抽取，但本次不引入新的运行时主题设置面板。

## 错误与降级

- 健康数据不可用时继续显示现有占位值和降级文案，首页环境光保持中性青绿。
- 加速度计不可用时保留点击模拟入口，并扩大人物的有效点击区域。
- 设备信息读取失败时采用 480×480 圆屏安全布局。
- 动画属性编译失败时删除对应装饰效果，不得用计时器模拟高频逐帧动画。
- 页面切换、隐藏或销毁后不得残留视觉定时器。

## 测试与视觉验收

自动测试覆盖：

- 父页面仍正确传递五个组件的业务 props 和事件；
- 方屏类与方屏契约已删除；
- 圆屏、紧凑圆屏和短视口所需类存在；
- 拳击人物区域继续发送 `simulatePunch`；
- 呼吸阶段类仍绑定 `breathPhase`；
- 业务逻辑、生命周期和发布构建测试不因视觉改造回归。

构建验收执行 `npm test`、`npm run build` 和 `npm run build:release`。

视觉验收必须实际运行应用并检查截图或模拟器画面，至少覆盖：

1. 首页正常状态与压力提醒状态；
2. 呼吸训练的吸气、停留和呼气阶段；
3. 节奏拳待机、目标、命中、连击和点击降级状态；
4. 两个结果页；
5. 480×480 圆屏、紧凑圆屏和短视口；
6. 所有标题、指标、提示、按钮和人物动作均未被圆形边缘裁切。

## 验收标准

完成状态必须同时满足：

1. 五个页面形成统一的深色赛博玻璃视觉语言；
2. 首页、呼吸训练、节奏拳和结果页具有已定义的智能分级动效；
3. 节奏拳中心主视觉是可识别、会随状态动作的霓虹线框拳击手；
4. 方屏专用布局与契约已移除，所有重要内容在圆屏安全区内；
5. 动效停止或降级后，全部状态和操作仍可理解、可点击；
6. 页面隐藏后没有新增视觉计时器或后台动画负担；
7. 自动测试、开发构建和发布构建通过；
8. 模拟器或等效渲染截图经过实际视觉检查，未发现圆屏裁切或遮挡。
