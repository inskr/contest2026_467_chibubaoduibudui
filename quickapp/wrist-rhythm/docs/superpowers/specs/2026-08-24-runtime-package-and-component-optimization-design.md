# 腕上节律运行时、包体与组件优化设计

## 目标

在不改变现有稳态训练和节奏拳规则的前提下，完成四类优化：

1. 压缩应用图标，并建立可复现的正式发布构建；
2. 降低节奏拳 50 ms 调度循环触发的无效响应式更新；
3. 在应用隐藏期间停止健康、动作和定时资源，恢复后继续剩余训练；
4. 将单体 `index.ux` 拆为一个页面控制器和五个展示组件，并补齐生命周期与假时钟测试。

优化不得破坏圆屏、方屏、紧凑屏、常规屏、宽裕屏和短视口适配。

## 当前问题

- `src/common/app-icon-512.png` 是 512×512 RGBA PNG，约 391 KB，占调试 RPK 的绝大部分。
- `npm run build` 生成开发包；正式构建入口和可核验的生产优化参数没有形成稳定契约。
- 节奏拳使用 50 ms 循环。循环需要保持评分时序精度，但当前每次都会给倒计时字段赋值，即使显示值没有变化。
- 健康订阅从页面就绪持续到销毁。应用隐藏时仍可能持有订阅，且训练计时器和动作传感器没有统一的暂停恢复语义。
- `index.ux` 同时包含五个视图、全部样式、页面状态机、系统适配编排和计时逻辑，难以独立验证生命周期和展示事件。

## 方案选择

采用“父页面控制器 + 无状态展示组件”方案。

未采用“各组件自行管理健康与传感器”的方案，因为它会产生多个系统资源所有者，使订阅幂等、暂停恢复和跨页面共享数据更难保证。未采用“只拆 CSS”的方案，因为它不能缩小页面控制器的模板职责，也不能形成清晰的事件边界。

## 组件架构

目标结构：

```text
src/pages/index/
  index.ux                    页面状态机与系统资源编排
  components/
    home.ux                   首页展示
    breathing.ux              呼吸训练展示
    steady-result.ux          呼吸结果展示
    boxing.ux                 节奏拳展示
    boxing-result.ux          节奏拳结果展示
  session-clock.js            可暂停的时间计算纯逻辑
  subscription-lifecycle.js   健康订阅幂等状态纯逻辑
```

现有 `steady.js`、`boxing.js`、`health.js`、`motion.js`、`layout.js` 和 `device.js` 保持各自职责。

`index.ux` 是健康订阅、动作订阅和定时器的唯一所有者。子组件只能：

- 通过 `props` 接收已格式化的文本、布尔状态、分数和屏幕布局字段；
- 通过组件事件报告 `startTraining`、`startBoxing`、`stopTraining`、`stopBoxing`、`simulatePunch` 和 `returnHome` 意图；
- 渲染自身模板和样式。

子组件不得导入系统 API、训练算法或设备适配器，也不得创建计时器。

圆屏、方屏和尺寸适配继续由父页面通过 `screenShape`、`screenSize`、`screenViewport` 传入。每个子组件保留自身所需的直接类选择器，避免使用 openvela 不支持的后代选择器。

## 生命周期与资源所有权

页面维护一个可见性状态和一个健康订阅状态。

### 首次显示

`onReady` 只负责读取设备布局和初始化页面。`onShow` 负责：

1. 幂等订阅心率和压力；
2. 仅在尚无健康值时请求最近样本；
3. 若存在暂停中的训练，则恢复训练时钟和对应运行资源。

### 隐藏

`onHide` 按以下顺序执行：

1. 记录训练暂停时刻；
2. 清除呼吸或拳击调度定时器；
3. 停止动作传感器和动作连接超时器；
4. 取消心率和压力订阅。

隐藏期间不累计训练有效时间。恢复时，将隐藏时长加入时钟的累计暂停时间，因此呼吸仍需完成 60 秒前台有效时间，拳击仍需完成 30 秒前台有效时间。

若应用在隐藏期间被销毁，不产生结果页，也不保留跨进程训练状态。

### 销毁

`onDestroy` 调用同一套幂等清理函数。重复隐藏、重复销毁或未成功订阅后的清理均不得抛错或重复调用系统取消接口。

## 可暂停训练时钟

`session-clock.js` 是无框架依赖的纯逻辑模块。它以显式时间戳工作，并提供以下行为：

- 创建指定时长的时钟；
- 查询排除累计暂停后的有效经过时间；
- 暂停时记录时刻，重复暂停无副作用；
- 恢复时累计暂停时长，重复恢复无副作用；
- 查询剩余秒数和完成状态。

呼吸周期、拳击节拍和结果规则仍由现有模块决定。时钟只负责有效经过时间，不调用 `Date.now()`；父页面在调用时传入当前时间，测试使用手工时间戳。

拳击恢复时不补发隐藏期间的节拍。恢复后从当前有效经过时间安排下一个节拍，避免用户因后台期间的不可操作目标被计为漏拍。

## 50 ms 调度优化

拳击保持 50 ms 调度，以支持 ±120 ms 的精准评分窗口。调度函数分为计算和提交两步：

1. 根据当前时间、时钟和拳击状态计算下一状态；
2. 只在字段的新值与当前响应式值不同时赋值。

允许写入响应式状态的事件只有：

- 显示倒计时秒数变化；
- 新节拍开始；
- 命中或漏拍；
- 心率区间导致节拍标签变化；
- 游戏完成或页面切换。

加速度样本仍直接进入纯动作检测器；没有命中时不触发界面写入。

## 健康订阅幂等

健康订阅管理必须明确区分“需要订阅的数据类型”和“当前已订阅的数据类型”。

- 第一次 `onShow` 对两种类型各订阅一次；
- 连续调用 `onShow` 不产生重复订阅；
- `onHide` 只取消实际已订阅的类型；
- 连续调用 `onHide` 不产生重复取消；
- 部分订阅失败不阻塞另一类型，后续显示可重新尝试失败类型。

`subscription-lifecycle.js` 只计算下一步需要执行的订阅或取消集合。实际系统调用仍由 `index.ux` 通过 `health.js` 完成，使纯逻辑可以直接在 Node.js 中测试。

由于应用不再需要隐藏期间的健康更新，从 `manifest.json` 移除 `service.health` 后台声明，但保留功能声明和健康权限。

## 图标压缩

项目内图标继续使用 512×512 PNG 和现有路径。压缩流程：

1. 将 RGBA PNG 量化为最多 256 色的索引色 PNG；
2. 保留透明通道；
3. 使用 PNG 优化器进行无损结构压缩；
4. 对比原图和压缩图的透明边缘、主体轮廓、渐变与品牌颜色；
5. 只有视觉检查通过后才替换项目内文件。

目标大小为 50–100 KB。若在可接受视觉质量下仍超过 100 KB，以视觉质量优先，并记录实际结果。临时备份位于系统临时目录，不提交到项目。

## 构建入口

保留快速开发构建：

```text
npm run build
```

提供正式发布入口：

```text
npm run build:release
npm run release
```

两条正式发布命令使用相同配置并生成 release RPK。正式配置必须启用：

- production 模式；
- JSC 字节码；
- CSS 属性优化；
- 删除 `console` 日志。

若 `aiot release` 已固定这些参数，则脚本直接复用该命令；否则使用工具链支持的显式配置文件或参数，不维护第二套自定义打包器。

构建验收记录原始图标、压缩图标、原调试 RPK、新调试 RPK和 release RPK 的字节数。包体优化以 release RPK 为正式指标，调试包只用于回归对比。

## 测试设计

所有新纯逻辑先按红—绿—重构实现。

### 假时钟测试

- 前台有效时间正确递增；
- 暂停期间有效时间不变；
- 恢复后从原剩余时间继续；
- 重复暂停和重复恢复幂等；
- 60 秒与 30 秒完成边界准确；
- 拳击恢复后不会补记后台漏拍。

### 生命周期测试

- 第一次显示产生两项订阅操作；
- 重复显示不重复订阅；
- 隐藏只取消已订阅类型；
- 重复隐藏不重复取消；
- 部分失败类型可以在下一次显示重试；
- 隐藏时定时器、动作连接超时器和传感器均由父页面清理。

### 响应式写入测试

- 50 ms 多次 tick 处于同一秒时，不重复提交倒计时；
- 秒数变化时只提交一次；
- 节拍、命中、漏拍和结束状态仍及时提交。

### 组件与集成测试

- 五个组件的输入契约覆盖现有页面所需字段；
- 六类用户事件正确进入父页面对应处理函数；
- 圆屏、方屏和短视口动态类完整传递；
- `npm test`、开发构建和 release 构建全部通过且无新增警告。

## 错误处理

- 设备信息失败继续使用安全的圆屏常规布局。
- 健康最近值或订阅失败继续显示现有降级文案，不阻塞训练。
- 动作传感器失败继续进入点击模拟模式。
- 页面隐藏时若资源已经停止，清理操作静默完成。
- release 构建若缺少正式签名或工具链配置，构建必须明确失败，不得回退生成标记为 release 的调试包。

## 验收标准

完成状态必须同时满足：

1. 五个视图已从 `index.ux` 移至独立展示组件，父页面仍是唯一状态与资源所有者；
2. 应用隐藏时没有健康订阅、动作订阅或活动计时器；
3. 返回前台后训练从剩余有效时间继续；
4. 拳击同一倒计时秒内没有重复响应式倒计时写入；
5. 圆屏、方屏、各尺寸和短视口适配仍能编译并保持操作可达；
6. 图标视觉检查通过且文件显著小于原始 390,550 字节；
7. 正式构建参数可从构建日志验证，release RPK 成功生成；
8. 全量自动测试、开发构建和 release 构建均通过且无新增警告。
