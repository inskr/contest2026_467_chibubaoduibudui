# 腕上节律 B1 棱镜夜光毛玻璃设计

## 目标

将现有 openvela 圆形手表应用升级为 B1「棱镜夜光」毛玻璃视觉系统，覆盖首页、稳态 60、节奏拳、稳态结果和拳击结果五个页面。

本次改造只调整布局、材质、色彩和状态动效，不改变健康数据读取、稳态判定、呼吸节奏、训练计时、拳击评分、动作传感器降级或前后台资源生命周期。

## 已确认的设计方向

- 视觉方向：B「棱镜夜光」；
- 能量分配：B1「冷静 / 爆发双能量」；
- 稳态 60：青蓝静息能量；
- 节奏拳：玫红爆发能量，琥珀只用于目标窗口和高连击瞬间；
- 动效强度：平衡型；
- 技术路线：保留现有五个展示组件，以业务状态驱动原生样式和动画类；
- 主题能力：本次不增加运行时换肤或设置面板。

## 视觉系统

### 固定材质

所有页面共享以下毛玻璃语言：

1. 深夜蓝低亮度画布；
2. 靛紫染色的分层半透明表面；
3. 低对比度 1px 边缘；
4. 轻微顶部高光和柔和内层光；
5. 深而扩散的阴影；
6. 克制的系统字体层级；
7. 一致的圆角、间距、透明度和信息层级；
8. 环境光可延伸到圆屏边缘，但不承载信息或交互。

不得使用粗白描边、整屏高饱和渐变、常驻粒子或塑料质感高光。画布和中性玻璃应占约 80% 的视觉面积，主题能量色约占 20%。

### 五色原始调色板

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| C1 Anchor | `#080B1D` | 页面画布和最深阴影 |
| C2 Primary | `#20245A` | 靛紫玻璃染色和中层环境光 |
| C3 Secondary | `#22D3EE` | 稳态 60、健康数据和静息反馈 |
| C4 Soft | `#FB7185` | 节奏拳人物、命中和拳击结果 |
| C5 Highlight | `#FBBF24` | 节拍目标窗口、高连击和少量瞬时高光 |

组件只按 `canvas`、`surface`、`calm`、`active`、`highlight`、`text`、`border` 等语义角色使用颜色，不以页面名散落任意色值。正文和关键数字继续使用中性白与灰，不使用琥珀作为大段文字色。

openvela 组件样式无法可靠共享浏览器式 CSS 变量，因此各展示组件保留相同的语义命名和完全一致的色值。本次不引入运行时调色引擎。

## 圆屏布局

设计基准为 480×480 圆形表盘，继续支持现有 `regular`、紧凑圆屏和短视口状态。

- 标题、指标、说明和操作位于中央安全区；
- 环境光、装饰环和阴影可以延伸到安全区之外；
- 文字和可点击区域不得依赖圆屏边缘；
- 动画不得推动标题、倒计时、指标或底部按钮；
- 紧凑圆屏通过已有尺寸类收缩间距和主视觉，不新增方屏布局。

## 五屏信息与视觉层级

### 首页

首页继续展示品牌、状态、心率、压力和两个训练入口。

中央生命仪表使用中性紫蓝玻璃，健康数据更新时触发一次青蓝或状态相关的外扩光环。压力偏高或趋势上升时只改变状态点、边缘和局部环境光，不改变结构。

稳态 60 入口使用青蓝弱强调，节奏拳入口使用玫红弱强调。琥珀不作为常态按钮底色。

### 稳态 60

青蓝呼吸球是页面唯一强主视觉，并直接绑定现有 `breathPhase`：

- `inhale`：4 秒平滑扩大并增亮；
- `hold`：2 秒保持尺寸并进行低幅悬浮；
- `exhale`：按当前 4 秒或 6 秒节奏收拢并留下柔和尾晕。

阶段文案、剩余时间和节奏说明保持固定位置。节奏变化继续由现有训练算法决定，视觉层不创建独立计时器。

### 节奏拳

保留可识别的线框拳击手和现有点击模拟区域。人物、目标环和反馈只消费父页面传入的状态：

- 待机：低亮玫红轮廓和轻量弹跳；
- 目标出现：琥珀目标环点亮，人物轻微蓄力；
- 命中：玫红短促出拳，拳端播放 300–500ms 冲击环；
- 漏拍：目标环快速变暗，不进行整屏红色闪烁；
- 连击：提高瞬时亮度和短拖影，不改变人物尺寸或布局；
- 点击降级：传感器不可用时继续点击人物区域模拟出拳。

得分、连击、剩余时间、节拍速度和降级文案保留当前数据来源和布局优先级。

### 稳态结果

入场时播放一次青蓝完成光环，随后回到低功耗静态玻璃。心率和压力变化使用低亮指标卡，改善状态可使用克制的青蓝强调。

### 拳击结果

入场时播放一次玫红完成光环。得分、命中和最高连击使用统一低亮指标卡；只有高分或高连击的瞬时反馈使用少量琥珀。

## 平衡型动效

动效由既有业务事件和状态触发，不建立第二套业务时钟：

1. 首页健康数据刷新时播放一次约 650ms 外扩脉冲；
2. 稳态 60 呼吸球跟随既有呼吸阶段持续运动；
3. 节奏拳只在目标、命中、漏拍和连击变化时播放短反馈；
4. 两个结果页只在入场时播放一次完成光环；
5. 应用隐藏或销毁后不保留视觉定时器，也不补播后台期间的反馈。

颜色、文案和数值始终共同表达状态，动效不是唯一信息来源。

## 组件边界与数据流

`src/pages/index/index.ux` 继续是页面状态、健康订阅、动作传感器、训练时钟、稳态结果和拳击评分的唯一所有者。

展示组件边界保持不变：

- `home.ux`：首页信息与训练入口；
- `breathing.ux`：稳态 60 展示；
- `boxing.ux`：拳击人物、目标和统计展示；
- `steady-result.ux`：稳态结果；
- `boxing-result.ux`：拳击结果。

展示组件只通过现有 props 渲染，通过现有事件报告用户意图。允许增加由既有业务事件派生的纯展示字段，例如脉冲代际或一次性入场类；这些字段不得复制训练计时、拳击评分或传感器状态。

## 错误处理与降级

- 健康数据不可用时继续显示现有占位值和降级文案，环境光保持中性紫蓝；
- 动作传感器不可用时保留点击模拟入口并维持足够大的拳击人物点击区；
- 设备信息读取失败时采用现有 480×480 圆屏安全布局；
- 动画属性不受支持时退化为颜色、透明度和尺寸状态类；
- 不使用高频 JavaScript 定时器模拟逐帧玻璃或粒子效果；
- 页面隐藏、切换或销毁后不得残留视觉资源。

## 测试与视觉验收

自动验证执行：

- `npm test`；
- `npm run build`；
- `npm run build:release`。

组件契约测试应继续确认五个组件的 props、事件、呼吸阶段类、拳击模拟点击和圆屏布局类。业务逻辑、评分、训练时钟、订阅与前后台生命周期测试不得因视觉改造回归。

视觉验收必须实际运行并截图检查：

1. 首页正常状态和压力提醒状态；
2. 稳态 60 的吸气、停留和呼气阶段；
3. 节奏拳的待机、目标、命中、漏拍、连击和点击降级状态；
4. 稳态结果和拳击结果；
5. 480×480、紧凑圆屏和短视口；
6. 所有标题、数值、提示、按钮和拳击人物均未被圆形边缘裁切。

## 验收标准

完成状态必须同时满足：

1. 五个页面形成统一的 B1 棱镜夜光毛玻璃系统；
2. 稳态 60 清晰使用青蓝静息能量，节奏拳清晰使用玫红爆发与少量琥珀高光；
3. 动效由现有业务状态驱动，后台停止且不承担唯一信息；
4. 业务逻辑、传感器降级和生命周期规则没有改变；
5. 关键内容和点击区域在所有目标圆屏状态下可见、可读、可达；
6. 自动测试、开发构建和发布构建通过；
7. 模拟器或等效渲染截图经过实际视觉检查。
